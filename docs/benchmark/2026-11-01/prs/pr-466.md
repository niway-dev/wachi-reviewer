## Notes

- No run found E3 (Back remounts the page and re-floats the card), the only difficulty-5 issue. The live Pullfrog run found it; neither replay Pullfrog did. The author fixed it later (84afb264, 059807d1), so it was real.
- Wachiman v1.3.0 found none of E1, E3, E4 in three replays, and only E2 once (R2). The live v1.2.0 run found E1 and E2. Its three batch-2 summaries all praise the `location.key` ref as correct ("asks once per arrival"), which is the code E3 shows is wrong on remount. Wachiman's summary text also stated "the CSS comments ... match" (R1) and "16 px padding ... matches" (R2/R3), repeating the claim E4 disproves.
- Wachiman's finding set differs across the three runs (A1+A2+A3, E2+A2, A1+A2): consistent only on A2. Variance is high on a 28-file PR; A2 (an Info doc nit) is the only finding present in every Wachiman run.
- CodeRabbit v1 caught E1 with a correct diagnosis and fix for the load-rejection case, but its fix (destroy window) does not restore the in-app fallback; the author's later fix resolves show() on card-ready instead. CodeRabbit v2 posted nothing actionable, although its Security Architecture section (walkthrough text, not counted) mentioned the unchecked `show` sender (E2) and `show()` returning true before readiness with fire-and-forget loading (E1), plus an unreported action-replacement race (B replaces A before A's action reaches main). That race is unconfirmed here.
- A4 (Pullfrog v2) is plausible but unconfirmed: Electron's `BrowserWindow.focus()` on macOS may not activate an inactive app, and the repo's own hub test says so for a different path. It was posted under an IMPORTANT banner without a runtime check, so I rated it Partly valid, not Valid.
- A1 mechanism exists in code (renderer keeps old payload; show is called right after send) but whether a frame is visibly painted depends on Electron's compositor on hide/show; unconfirmed, and unfixed on origin/main.
- Pullfrog v1 and v2 each posted a different set (E4 only vs A4+A2) with no overlap, so Pullfrog is also unstable on this PR; v1 found a real difficulty-4 cross-file issue (CSS shadow vs window padding) that no Wachiman run noticed.
- E4's severity is Low; Pullfrog's "reaches about 80px below" is correct (30 offset + 80 blur - 30 spread = 80).
